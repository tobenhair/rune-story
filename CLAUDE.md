# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**rune-story** is a self-contained, single-file browser RPG called **AstralBound** — a pixel-art 2D platformer set in the world of Aethoria. The entire game lives in `index.html` (~3,000 lines). There is no build system, no package manager, no external dependencies, and no configuration files.

## Running the Game

Open `index.html` directly in any modern browser. No server required.

```bash
# macOS
open index.html

# Linux
xdg-open index.html

# Or serve locally if needed
python3 -m http.server 8080
```

## Testing & CI

The game logic is covered by a **Playwright** suite in `tests/` that loads `index.html` in headless Chromium and drives the real game functions/state via `page.evaluate` (the RAF loop is cancelled so time is stepped deterministically). A shared fixture (`tests/fixtures.js`) boots the game and exposes in-page helpers (`window.T`: `withRandom`, `clear`, `resetPlayer`, `mon`). Specs are organized by domain: `boot`, `zones`, `monsters` (+ affixes), `combat`, `skills`, `gear` (+ forge), `quests`, `economy`, `bosses` (+ enrage), `movement` (dash/i-frames), `render` (every zone draws without error: sprites, props, foreground, lighting), `display` (responsive canvas fit + fullscreen, world-space label pills / NPC role glyphs, quest-tracker hierarchy), `coreloop` (movement-demanding enemy behaviors incl. shielded/bomber archetypes, safe portal entrances + boss dormancy, relic pity rework, per-zone exploration caches). Rift arena variety (theme/layout rotation + deep-Echo riders) is covered in `rift`. The vertical world — tall climbable combat zones (`camY` camera, `CZ.ladders`, `towerZone`) and the limited horizontal attack cone (`AIM_CONE`) — is covered in `vertical`.

```bash
npm install                                  # installs @playwright/test
npx playwright install --with-deps chromium  # one-time browser download
npm test                                     # runs the suite (playwright test)
```

CI runs the suite on every pull request and on pushes to `main` via `.github/workflows/tests.yml`. **When adding or changing game content/systems, add or update the matching spec** so the suite stays a complete content inventory. Linting is still not used; the game itself remains a single inline `index.html`. Beyond the automated suite, final feel-checks (animation, audio, difficulty) are still worth doing by opening the game in a browser.

## Architecture

The file is one HTML document with all CSS, JavaScript, game data, rendering, and audio inline. Code is organized into logical sections by line range:

| Section | Lines | Responsibility |
|---|---|---|
| Audio Engine | ~216–318 | Procedural music and SFX via Web Audio API (no audio files) |
| Cutscene System | ~320–853 | Narrative scenes rendered to Canvas 2D (intro + three finale scenes, `playScene`) |
| Sprite System | ~900–1130 | Hi-res 32×48 pixel sprites generated at runtime (no image assets) |
| Game Engine | ~883–1220 | State, physics, combat, quests, skills, main loop |

### Global State

All mutable game state lives in a single `G` object defined in the Game Engine section. Player stats, inventory, active quest progress, zone index, and runtime flags are all properties of `G`.

### Persistence

Progress is saved to `localStorage` under the key `astralbound_save_v1` (`saveGame()` / `loadSave()` / `applySave()` in the Game Engine section). Saves happen automatically every 10 seconds during play, on major events (kills, quest accept/turn-in, purchases, skill unlocks, item use, zone travel), and when the tab is hidden or closed. The save snapshots `G` (minus transient combat flags like the active shield), the `USK` skill set, `bossTimers`, and volume slider values. The payload carries a `v` field: v1 saves (pre-city-hub) are migrated on load — zone indices and boss timers shift by 1 and legacy gear id strings convert to gear objects. On boot, an existing save skips the intro cutscene and shows a "Continue" button on the character screen; starting a new game over an existing save requires a second confirming click (no native `confirm()`, which can be blocked in sandboxed embeds). New persistent fields must be added to all three of `saveGame()`, `applySave()`, and the `G` initializer.

### Input

Keyboard input drives the `keys` (held) and `jp` (just-pressed, cleared every frame) maps. Touch controls reuse the same maps: on-screen left/right/jump buttons (plus a contextual Talk button near NPCs and a Dash button) are overlaid on the canvas and enabled automatically on coarse-pointer devices or on first `touchstart`. Tapping the canvas casts at the nearest monster / talks to NPCs via the existing click handler.

**Dash:** **Shift** (or the touch `tb-dash` button → `jp['dash']`) triggers a dodge dash — a short horizontal burst (`DASH_SPD`/`DASH_TIME`) with invulnerability frames (`DASH_IFRAME`, applied via `PL.inv`) and a cooldown (`DASH_CD`). Dash state lives on `PL` (`dashT`/`dashCd`/`dashDir`/`trail`); the `trail` array drives fading afterimages drawn just before the player sprite. Dash fields are reset on `respawn()` and `loadZone()`. Because i-frames raise `PL.inv`, dashing passes through both melee contact and hostile projectiles (all gated on `PL.inv<=0`).

**Climbing (ladders).** Tall combat zones stack platform tiers taller than the screen; wooden **ladders** (`CZ.ladders`, `{x,y1,y2}`) link them. Holding **Up/Down** while overlapping a ladder (`ladderAt(x,y)`) mounts it (`PL.climbing`): gravity is suspended and the player moves vertically at `CLIMB_SPD`, passing through platforms until they step off sideways or jump. So the up-arrow only doubles as jump when **not** on a ladder (`J = jp[' '] || (jp['arrowup'] && !PL.climbing)`); **Space** always jumps (and hops off a ladder). `PL.climbing` is reset in `loadZone`/`respawn`.

Spells are bound to **Q W E R**. **Aim is limited to a horizontal cone** (`AIM_CONE`, ±20°): auto-targeting (`closest`) and click-casting only acquire non-boss foes within the cone of the cast origin, and `fireAt` clamps a non-boss shot's angle to it — so you can't snipe a whole tower from the floor; you climb to a foe's level to hit it. **Bosses are exempt** (`inAimCone`/`fireAt` skip the clamp when `tgt.boss`), keeping arena fights free-aim. Consumables use a two-slot **potion hotbar** bound to **T** and **Y** (`G.hotbar` holds the assigned item ids): click a slot's icon (or press its key) to use the assigned potion, click the slot's label to open the assign/clear picker (`openHotbarAssign`/`assignHotbar`). Newly acquired consumables auto-bind to the first empty slot via `autofillHotbar()` (called from `addItem` and storage withdrawal). `renderHotbar()` keeps the icons and quantity badges in sync and is called from `renderIP`/`renderAll`. The hotbar persists in saves like other `G` fields.

### Zone Data

Static zone definitions live in `ZD` (an array of 10 objects). Zone 0 is **Aethon City**, a safe hub with no monsters where every NPC (quest givers and shops) lives; zones 1–4 are Act 1 combat zones with no NPCs. Zone 5 is **The Hollow Rift**, the hidden Act 1 final-boss arena: it has no regular monsters and is unreachable from the map modal — the only way in is the teleport fired when the Act 1 finale (`tp:5`) is accepted, or the "Return to …" button shown while a `tp` quest is active (the button/log text derives from `ZD[q.tp].name`); the only way out is its edge portal back to the hub. Zone 6 is **The Endless Rift**, the endgame wave-survival arena (`RIFT_ZONE`) — also off the map, entered only via the Riftwarden's gate and left via its edge portal (see The Endless Rift below). Zones 7–8 are the **Act 2 combat zones** (Emberfall Wastes, Frostveil Glacier) — appended *after* the arenas so the load-bearing indices 5/6 never shift; they appear on the map modal only once Act 2 is open (`actTwoOpen()` = q15 done; `buildMap` lists `[0..4]` plus `[7,8]` when open). They also lie physically **west** of the hub and are walkable: the hub's west edge portal leads into Emberfall Wastes, whose own west portal continues to Frostveil Glacier (city ← zone 7 ← zone 8, each east portal walking back the same chain). `enterPortal` refuses portals into zones 7–8 until `actTwoOpen()`, and `drawPortals` draws them dimmed with a "Sealed by ash" label until then (then falls back to the generic `G.level < req` lock). Zone 9 is **The Ashen Sanctum**, the Act 2 finale arena — teleport-only (q22 `tp:9`), boss spawned on entry by `loadZone` (same as zone 5), exit via edge portal. Zone 10 is **The Riftheart**, the true-final raid arena (q23 `tp:10`, same teleport-only pattern) — see the raid bullet in Content Reference. Each zone contains platform geometry, monster spawn data, NPC placement, and edge portals (`portals`). Zones are accessed by index; transitions happen via the map modal or by walking into a portal and pressing F (or the touch Talk button). Zone level locks come from each zone's `req` field — no hardcoded index checks.

**Tall combat zones (vertical exploration).** The six combat zones (1–4, 7–8) are built by the `towerZone({name,sky,bound,req,cols,mons,portals})` generator: eight platform tiers stack upward from a low ground line, alternating left/right, with wooden **ladders** (`CZ.ladders`) placed in each tier's overlap (they form a central climbing spine plus a ground-access rung). The entry carries `h` (tall world height), `ground` (low world-space ground Y), `ladders`, tier `plats`, and vertically-spread `mons`. Each zone's hidden `ZONE_TREASURE` cache now sits on the **top tier** (a real climb to reach). The generator is deterministic so specs stay stable. The hub (0) and every arena (5, 6, 9, 10) keep their original single-screen layouts (no `h`/`ground`/`ladders`), so `camY` stays pinned there. Combat-zone **bosses** spawn near the new ground (`BOSS_DEFS` `sx`/`sy` lowered) so the fight happens at the tower base where the player enters. `loadZone` derives `zGround`/`zHeight` from `CZ.ground`/`CZ.h` (defaults 388/480); the player spawns at `zGround-128` and the fall-pit / off-screen monster resets are relative to `zGround` (so the classic values fall out for short zones).

**Safe zone entrances** (C2). Three guards keep the teleport-in point from being a death-trap: (1) `loadZone` grants ~1s of entry i-frames (`PL.inv` bumped to 1.0) so nothing lands during the zone-card wipe; (2) a **no-aggro safe radius** — `pSafe` (computed once per frame, true while the player is within 150px of any portal in `portals2`) suppresses trash chase, melee, lob and leap-start (bosses are exempt), so entrances/exits are breathers; (3) **arena boss dormancy** — the global `combatStarted` (reset to `false` in `loadZone`, flipped `true` on the first move/jump/dash/spell input or click-cast in `fireAt`) freezes a non-anchored boss at its spawn (`m.x=m.bx`, no `updateBossAbilities`) until the player acts, preventing spawn-camping at the finale/rift teleport point.

**Finale stakes** (E2). While a finale-arena boss lives (`finaleSealed()`), the arena's exit portal is sealed: walking it opens a confirmed "retreat resets the fight" dialog (leaving returns to the hub and the boss respawns at full strength on re-entry), and `drawPortals` draws it locked with a "Defeat the boss to leave" / "[F] Retreat?" label. Turning in the milestone quests plays a short finale scene (E1): q15 (the door closes), q22 (Malachar falls / the Zal'Guroth reveal), and q23 (the true ending) via `playScene`, reusing the intro's scene art. The intro itself now comes *after* naming (`beginNewGame`), so it personalises with `{name}`.

### The Endless Rift

The post-story endgame: an infinitely scaling wave-survival mode (the flagship retention feature). All state lives on a transient global `RIFT` object plus two persistent `G` fields (`riftBest`, `riftShards`). Players talk to **Riftwarden Kael** (a `rift:true` NPC in the hub; `openDlg` routes to `openRift`) — gated by `riftUnlocked()` (final boss killed or `q15` done) — and choose a starting **depth**. `startRift(d)` loads the arena (`RIFT_ZONE`), and `updateRift(dt)` (called at the end of `update`) drives the loop: each **depth** is a set of waves (`riftWaveCount`) of depth-scaled monsters (`mkRiftMon` ramps HP/damage/xp by depth and active modifiers; `spawnRiftWave`), with a boss **Echo** (`spawnRiftBoss`, a depth-scaled reuse of a `BOSS_DEFS` entry) every 5th depth. Clearing a depth (`depthCleared`) banks **Rift Shards**, updates `riftBest` (with a new-record bonus), and opens a **curse draft** (`openRiftDraft`/`pickRiftMod`): one of three `RIFT_MODS` that ramp danger for a cumulative `shardMul`. Death in the rift routes through `respawn` → sets `RIFT.ending` → `endRift(false)` next frame (banked shards are kept); walking the edge portal calls `endRift(true)` (`enterPortal` intercepts). Shards are spent at the Riftwarden on `RIFT_SHOP` caches (`buyRift`). The rift HUD (depth/wave/banked/mods panel + transition banner) draws at the end of `draw()`. `saveGame` records the hub zone (never `RIFT_ZONE`) while a run is active, and `applySave` redirects a stray `RIFT_ZONE` to the hub.

### Ascension (prestige / New Game+)

The meta-progression layer that gives the endless loop long-term meaning. All meta state lives on a global `META` object (`{asc,echoes,talents}`) persisted under a **separate** localStorage key (`META_KEY = 'astralbound_meta_v1'`, `saveMeta`/`loadMeta`, loaded once at boot) so Ascending can soft-reset the run (`G`) without wiping permanent unlocks. **Astralwright Nyx** (an `asc:true` hub NPC; `openDlg` → `openAscension`) is gated by `canAscend()` (= `riftUnlocked()`). `ascend()` is a two-click confirm (`ascArmed`) that banks **Astral Echoes** (`ascEchoes()`, scaled by level + `riftBest` + prior ascensions), increments `META.asc` (the paragon level), then resets the character (level/xp/hp/mp/gold/skills/quests/equipment/inventory/spells/bounty/hotbar/`USK`/`bossTimers`) while **keeping** the storage vault, rift progress (`riftBest`/`riftShards`), and `META`. Echoes buy permanent ranks on the `ASCN` talent board (`buyAscn`). **Invariant:** every paragon multiplier is exactly neutral at `META.asc=0` with no talents, so a never-ascended game (and the test suite) is unchanged. The multipliers plug into single chokepoints: `ascEnemyMul()` (enemy HP/damage in `mkMon`/`spawnBoss`/`spawnRiftBoss`), `metaRewardMul()` (XP/gold at spawn), `metaDmgMul()` (spell damage in `fireAt`), `metaCrit()` (bonus crit in the projectile-hit path), `metaDropMul()` (gear drop rate in `killM`), `metaShardMul()` (shard gain in `depthCleared`), and `metaStartHp/Mp/SP()` (starting stats applied on ascend). The level HUD shows the ascension count via `lvlLabel()`.

### Build systems — runes, respec & the living hub

Two layers that deepen builds and give gold a long-term home; both are **runtime-computed and neutral by default** (nothing socketed / no districts raised), so a fresh game is unchanged.

**Runes & sockets (`RUNES`).** Gear gains an optional `g.sockets` array. Sockets are **drilled** at the Forge for gold (`drillSocket`, capped by `maxSockets()` — base 2, +1 per Grand Forge level); runes are then slotted (`socketRune`/`unsocketRune`, picker via `openSocketPicker`). Each rune id is injected into `ITEMS` so runes stack/sell/store like materials (and are excluded from bulk-sell). Bonuses are summed at runtime via `socketedRunes`/`runeSum` and fold into single chokepoints: `eqMag`/`eqDef` (mag/def), the crit path (`runeCrit`), the mana-regen line (mpregen), the projectile lifesteal (`runeSum('lifesteal')`), and kill XP/gold (`runeFind`). Runes are bought at the Forge (`buyRune`, `RUNE_PRICE`) or from the rift `Runic Cache`.

**Respec (`respec`).** A free in-town reset: refunds every spent skill point (including the full triangle cost of Attunement ranks), clears `USK`, resets `G.attune`, reverts the `mf`/`vt` stat bonuses and the `fb`/`is` spell unlocks. Button lives in the skill panel (`renderSP`).

**Astral Attunement (`G.attune`).** The infinite skill-point sink for the post-tree band (the 13-node tree costs 26 points; players reach the raid at ~35): a repeatable node rendered below the tree in `renderSP` — rank *n* costs *n* points (`attuneCost`) and grants +4% spell damage (`attuneMul`, applied in `fireAt`). Reset by `respec` (refunded) and by `ascend`. Persists like any `G` field.

**Greater Runes (`RUNES` `greater:true`, `GREATER_CRAFT`).** Tier-2 runes at ~double stats, never sold: crafted at the Forge (`craftRune`, section gated on `actTwoOpen()`) from 2× the base rune + 4× an Act 2 material + `GREATER_GOLD`×`forgeDiscount()`. This is what Ember Chunks / Ash Feathers / Rime Fangs / Glacial Dew are for. They stack/store/socket like base runes (same `ITEMS` injection, `rune:true`).

**Emberstorm (`G.emberstorm`).** A spell mutation taught by q22's turn-in (`rew.teach==='emberstorm'`, handled in `turnInQ`): every Fireball hit splashes 40% damage to enemies within 90px (armored-reduced, spreads the Inferno burn when learned; never affects `invuln` targets). Lives in the fireball branch of the projectile-hit path; reset by `ascend`, persists in saves.

**School capstones.** Three build-defining `SKN` nodes gated on the existing tree: `inferno` (req `py` — Fireball applies a burn DoT, ticked in the monster AI loop via `m.burn`/`m.burnDmg`), `chain` (req `as` — Arcane Bolt arcs to a 2nd enemy), `glacier` (req `fr` — Ice Shard deep-freezes nearby foes). All effects live in the projectile-hit path and run only when learned.

**The living hub (`CITY`, `G.city`).** **Master Builder Sora** (a `town:true` hub NPC; `openDlg` → `openCity`) sells permanent district upgrades for gold (`upgradeCity`, cost ramps via `cityCost`). Each district feeds one chokepoint: Arcane Sanctum → mana regen (`cityLvl('sanctum')` in the regen line), Grand Forge → `forgeDiscount()` (upgrade/drill/rune cost) + `maxSockets()`, Apothecary → `potionPotency()` (in `useItem`), Mercenary Guild → `bountyMul()` (in `genBounty`), Reinforced Vault → storage-expansion discount (in `storageCost`). The hub skyline grows with `cityTotal()` (a monument drawn in `drawCityBG`) **and per district** (`drawCityDistricts`, called from `drawCityBG`): each district's building appears on the skyline at level 1 and gains one visible piece per further level — HoMM-style town growth (apothecary windows/planters/cauldron, forge chimney/smoke/furnace glow, vault stone tiers/door/gold glint, sanctum tower segments/orb/orbiting motes, guild banners/braziers/trophy skull). Purely cosmetic; nothing is drawn at level 0, so a fresh city looks unchanged. `G.city` is added to the `G` initializer, `saveGame`, and `applySave`.

### Engagement — Daily Rift, Achievements & the Codex

The retention/again-hooks layer; **all state is account-wide on `META`** (persisted under `META_KEY`, so it survives Ascension). Persistence is bounded: `saveMeta()` runs alongside `saveGame()` in the 10s autosave (`tick`), on tab hide/close, and whenever an achievement unlocks.

- **Daily Rift.** A deterministic once-a-day challenge built on the rift engine. `dailyMods()` picks a fixed two-curse loadout from the UTC date via a seeded PRNG (`mulberry32`/`dailySeedNum`) — the same trial for everyone, fully offline. `startDaily()` (a button in the Riftwarden dialog, gated by `dailyDone()`) sets `RIFT.daily=true` and pre-applies the mods; `endRift` routes a finished daily run to `dailyComplete(reached)`, which records `META.daily` (`{date,streak,best}`), advances the streak when yesterday was done, and pays streak/depth-scaled shards.
- **Achievements (`ACHV`).** ~24 account-wide milestones whose `c()` predicate reads live state or `META.flags`. `checkAchv()` unlocks any newly-true ones (into `META.achievements`), pays a **Rift Shard** reward, and is called from the event sites that can satisfy a condition (`killM`, `gainXP`, `turnInQ`, `addGear`, `upgradeGear`, `socketRune`, `upgradeCity`, `depthCleared`, `ascend`) plus the autosave. One-shot conditions set a `META.flags.*` flag at their moment (legendary/artifact/forged/runesmith/builder/elite/daily).
- **Codex / Bestiary.** `bestiaryList()` (derived from `MDEF` + `BOSS_DEFS`, lore in `CODEX_LORE`) is shown by **Chronicler Ily** (a `codex:true` hub NPC; `openDlg` → `openCodex`, which also toggles to the achievements view). Creatures unlock as they're slain — `killM` records `META.codex[type]` and increments `META.totalKills`. `renderCodex` shows discovered creatures' stats/lore and `???` for the rest.

### Game Loop

The main loop uses `requestAnimationFrame`. Each frame calls:
1. `tick(dt)` — updates physics, AI, cooldowns, combat, input
2. `draw()` — renders background layers, entities, and UI to canvas

### Rendering

Everything is procedural Canvas 2D. Backgrounds use multi-layer parallax (depths 0.2–0.9). Sprites are generated into off-screen canvases at startup and indexed for animation frames. No image files are ever loaded.

**Responsive display.** The world renders at a **fixed 16:9 internal resolution** (`VIEW_W=854`/`VIEW_H=480`, set on `cv.width`/`cv.height` in `setupCV`) rather than the old "size the bitmap once to whatever the container happened to be" approach. **The camera scrolls both axes**: `camX` (horizontal, always) and `camY` (vertical). Short zones (hub, arenas — no `CZ.h`) keep `zHeight=480`/`zGround=388` so `camYMax()` is 0 and `camY` stays pinned at the top, framing exactly as a single 480-tall screen (content y≈78–406). Tall combat zones (see Zone Data) set `CZ.h`/`CZ.ground`, and `camY` follows the player (clamped `[0, camYMax()]`, i.e. top-of-world at screen top → ground at screen bottom). Rendering applies `camY` via a single `ctx.translate(0,-camY)` around the **world layer** (platforms, ladders, props, entities, projectiles, FX, player); the sky, ambient foreground, lighting grade/vignette and all HUD/overlays stay screen-fixed (the few world-anchored bits outside the translate — the player/projectile lights in `drawLighting`, DOM damage numbers in `spawnDN`, and `onCC`'s click→world Y — subtract `camY` manually). `fitCanvas()` sets the canvas element's CSS `width`/`height` to the largest aspect-preserving box that fits `.cw` (called on boot, `window.resize`, and `fullscreenchange`); the leftover is a centered letterbox, and because the drawn box equals the styled box, `onCC`'s click→world mapping stays exact. The shell (`#gr`) fills the viewport (`100dvh`) and the active `.screen` fills the shell, so there is no dead page gutter. A `⛶` HUD button calls `toggleFullscreen()` (requests fullscreen on `#gr`). Tests that need a real backing store set their own `cv.width`/`cv.height`, so the fixed resolution doesn't constrain them.

**World-space labels** (`labelPill`). `labelPill(text,cx,baseY,{size,color,bg,border,alpha})` draws a dark rounded backing pill under centered pixel-font text so names read over the parallax. NPC names, monster names and portal names all route through it: pills show on proximity (bosses/elites/portals always on); far entities fall back to a faded plain label. Hub service NPCs also get an always-visible role glyph above their head via `npcRoleIcon(n)` (`NPC_ROLE_ICON` maps `forge`→⚒️, `shop`→🛍️, `storage`→📦, `board`→📋, `codex`→📖, `rift`→🌀, `asc`→✨, `town`→🏛️); pure quest-givers show only the existing gold `!`/`?` marker.

**Side-panel & HUD UX** (roadmap P4). The skill panel (`renderSP`) groups nodes into colour-coded **Arcane/Fire/Frost** sections (each `SKN` node has a `sch`) with connector-indented sub-skills and a "↳ Requires X" line on locked nodes. Bag/equipped tiles show rarity-coloured borders and a hover **inspection tooltip** (`#tip`, `itemTipHTML`/`gearTipHTML`): name, stats, sockets, artifact power, a Δ compare vs. the equipped item, and sell value. The combat log keeps combat/loot lines; quest-state and achievement messages route to transient **top-right toasts** (`toast()`, `log()` diverts type `'q'`). An **Esc pause menu** (`togglePause`, `#pause`) freezes the update loop and hosts the relocated music/SFX/reduced-motion controls (`movePauseSettings`), How-to-Play, and Quit to Title. The **codex** groups the bestiary by zone (`monZoneMap`) with per-zone counts and shows a blacked-out silhouette + zone name for undiscovered creatures. A third potion hotbar slot (`U`) unlocks at Apothecary level 3 (`hotbarSlots`). Two zones are lit against the signature darkness (A4): Village Outskirts as warm dawn, Frostveil Glacier with an aurora tint (`ZGRADE`).

**Per-zone exploration** (C3). Each combat zone has one hidden treasure cache (`ZONE_TREASURE`) on its hardest-to-reach top platform — a guaranteed rare+ gear drop + gold, once ever (`openTreasure`, tracked in `G.treasures`); a faint glow marks it, a name pill shows only up close. A rare wandering elite (~30%) may prowl a combat zone on entry.

**Combat-intensity music** (F1, wants a human listening check). `updateCombatMusic` (called from `tick`) swells a persistent bass layer (`combatGain`) with nearby threat and runs a slow ~90s filter sweep for long-cycle variation.

**Sprite resolution.** Sprites are authored on a hi-res **32×48** internal grid (`SD`/`SDH` = `SW*SS`/`SH*SS`, `SS=2`) for shading, outlines and faces, then drawn into the unchanged on-screen footprint (`SW*SCALE × SH*SCALE`). All gameplay math — hitboxes, the boss/elite `bScale` multipliers, projectile offsets — still uses `SW`/`SH`/`SCALE`, so the supersample is purely cosmetic. Every `draw*` sprite function clears and paints `0,0,SD,SDH`; the six `drawImage` blit sites (preview, HUD, NPC, monster, dash trail, player) read source rects in `SD`/`SDH`. Shared sprite helpers: `vg` (vertical 3-stop gradient body shading), `orc` (outlined rect), `band` (light/dark banding), `glow` (radial glow for eyes/orbs), `fx` (mirror an x-coord so R-facing sprites author once and flip for left).

**Environment polish layer** (cosmetic, layered over the per-zone parallax BGs). `zoneTheme(z)` maps each zone to a theme; three passes run inside `draw()`: `drawProps()` (world-space ground decorations — trees/crystals/columns/lampposts/obelisks, behind characters), `drawForeground()` (ground fog + animated ambient particles — leaves/embers/spores/fireflies — and a translucent foreground silhouette band, in front of characters), and `drawLighting()` (per-zone colour grade via `ZGRADE` + a warm radial light on the player + spell-coloured light per live projectile + a vignette, under the HUD). All are procedural and add no new `G` state.

### Audio

All sound is synthesized via Web Audio API oscillators and noise. Zone music is generated algorithmically per-zone. SFX (spells, hits, levelup, death, crits) are short procedural bursts. No audio files exist.

## Key Constants

```js
GRAV = 900        // Gravity (px/s²)
JUMP = -390       // Jump velocity
SPD  = 175        // Horizontal speed cap
CLIMB_SPD = 140   // Ladder climb speed (px/s)
AIM_CONE  = π/9   // ±20° spell-aim cone (non-boss targets)
```

Combat damage includes ±random variance. Skill `Arcane Mastery` adds +20% spell damage; crits deal 2× with 20% chance when `Arcane Surge` is unlocked.

XP to next level scales as `xpNext *= 1.4` per level up to 16, then **flattens to `*= 1.15`** from level 16 on (`gainXP`) so the late-Act-1 (16–20) and Act 2 (20–30) bands stay reachable without grind walls; `applySave` caps an inflated pre-flattening `xpNext` at the canonical value for the save's level. Zone 2–4 kill XP is rescaled to bridge the ramp (bat 48, golem 200, skeleton 150, wraith 190); Act 2 monsters/quests pay XP in the thousands/tens-of-thousands. Each level grants +20 HP, +10 MP, and 1 skill point. Pacing was tuned against a quest-by-quest simulation: the efficient-path campaign is ~3h with no single grind wall over ~25 min (bounties shrink those further).

See Architecture › Build systems.

A deterministic daily challenge (`dailyMods`, **Riftwarden** dialog), ~28 shard-paying achievements (`ACHV`/`checkAchv`, incl. Act 2's `malachar`/`saga2` and the raid's `hollowone`), and a bestiary that fills as creatures are slain (`bestiaryList`/`CODEX_LORE`, **Chronicler Ily**). See Architecture › Engagement.
- **Monsters**: Slime, Goblin, Bat, Golem, Skeleton Archer, Shadow Wraith (Act 1); Magmite, Ashwing, Frostmaw, Sleet Wisp (Act 2, zones 7–8 — thousands-scale XP, also appended to `RIFT_POOL` so they surface in deep rift descents, and to `BOUNTY_POOLS[7]`/`[8]`). Spawns roll a 10% Elite chance (`mkMon`): ★-prefixed, 3× HP, 1.5× damage, 2.5× XP, 3× gold, golden glow, drawn larger. Gear drops are 1% per kill for normal **and** elite kills (elites get boosted rare+ rarity when they do drop — they are no longer a guaranteed drop); see Equipment. Dying drops 10% of carried gold. Boss respawn countdown is drawn top-right of the canvas in boss zones. **Elite affixes** (`AFFIXES`, rolled in `mkMon`, stored on `m.affix`/`m.affixC`): `frenzied` (×1.5 move + faster attacks/ranged), `vampiric` (heals 50% of melee damage dealt), `explosive` (AoE detonation on death, handled in `killM`), `armored` (takes 40% less spell damage). The affix name is prepended to the monster name and tints its glow/label. **Movement-demanding behaviors** (`beh` on `MDEF`, carried onto instances by `mkMon`, handled in the monster-AI loop): `leap` (goblin, frostmaw — telegraphs a crouch via `m.leapWind`, then springs in a ballistic arc; the base ground-follow is suppressed while `m.leaping`/`m.leapWind`), `aura` (golem `#b06cff`, magmite `#ff7a30` — a DoT field of radius `m.auraR` that ticks every 0.5s while the player stands inside, forcing a kite; a pulsing ground ring telegraphs it), and `lob` (skeleton, sleetwisp — arcs a `grav:true` hostile projectile onto the player's position via a fixed-flight-time ballistic solve, so it reaches ledge-campers; generalizes the old skeleton straight-shot). Onset sets `m.enraged` (one-time banner + 🔥 marker + red aura) to punish endless kiting. Each combat zone's signature monster also has a **1% rare-relic drop** in its `loot` table (Slime→`rift_seed`, Bat→`wither_heart`, Golem→`resonant_core`, Skeleton→`rift_sigil`, Magmite→`ember_heart`, Frostmaw→`frozen_tear`) — these are the targets of the per-zone rare-hunt quests. **Relic bad-luck protection**: every dry kill of a relic-carrying monster increments `G.relicPity[item]`; from 25 misses the drop chance ramps +2%/kill (capped at 100%, so a hunt is effectively guaranteed by ~75 kills), and a drop resets the counter. Visible progress hints fire at 25 (“…the rift-song grows louder…”) and every 10 kills after, so the hunt never feels dead. `relicPity` persists like any other `G` field (initializer, `saveGame`, `applySave`).
- **The Riftheart raid (q23)**: the true finale — **Zal'Guroth, the Hollow One** (`hollow_idol`, zone 10, `noEcho`), the Voice that controlled Veyra and Malachar. A Zakum-style multi-part fight (~10 min): the colossal anchored idol (`bscale 7`, giant full-sprite hitbox in the projectile path) is **immune** (`m.invuln` — projectiles splash "IMMUNE", auto-target skips it) while six **Arm of the Hollow One** part-bosses (`IDOL_ARM`/`spawnIdolArms`, `m.part` = XP/gold only, no gear) hover anchored around it with role-cycled attacks (gravity-lob crusher / aimed gazer / 3-way render — `p.grav` projectiles arc). Stage 2 (all arms dead): core exposed — 8-way Void Ring, gravity Hollow Meteors, a knockback Hollow Crush. Stage 3 (<40% HP): the third eye opens — cadence ×0.62, aimed Hollow Lances, two arms regrow. Raid-length enrage (`m.enrageAfter` 480s). Guaranteed Artifact + `hollowone` achievement on the kill. Engine support added for the raid: `m.invuln`, `m.anchored`/`m.ay`/`m.bobAmp` (stationary hovering monsters skip the walk/melee AI), `p.grav`, per-boss `m.enrageAfter`, and text damage-numbers (`spawnDN` accepts a string).
- **Spells**: Arcane Bolt, Mana Shield (base); Fireball, Ice Shard (skill unlocks)
- **Skills**: Arcane Mastery → Fireball → Arcane Surge / Pyromancy; Mana Flow → Ice Shard → Deep Frost; Mana Flow → Greater Ward; Vitality and Gold Sense (passives)
- **Equipment**: procedural gear drops (`rollGear`) with 6 rarity tiers (`RARS`) and 6 zone-scaled base tiers (`GEAR_BASES` — Act 2 zones roll the Emberforged/Rimeheart tiers via `ti = zi-3` for `zi>=7`): Common→Legendary plus **Artifact** (tier 5). Weapons add flat magic damage (`eqMag`), armor adds defense (`eqDef`) and max HP. **1% drop chance per kill** (normal and elite alike; `rollGear(G.zone,m.elite)` in `killM` — elite kills roll boosted rare+ rarity), guaranteed rare+ from bosses (the final boss `hollow_oracle` also drops a guaranteed Artifact). Looting or forging a Legendary triggers `celebrateLegendary()`: a swirling gold particle column + fireworks around the player, a banner, and a synthesized trumpet fanfare (`sfxFanfare`). Quest-reward gear ids convert to gear objects via `GEAR_FIXED`. Click bag items to equip, equipped slots to unequip.
- **Artifacts**: a fixed pool (`ARTIFACTS`) of unique boss-only items (1% drop per boss kill, rolled in `killM` in addition to the guaranteed rare+). Each carries a special `pow` whose effect is applied at runtime via `hasPow(id)` and described in `POW`: `lifesteal` (heal 15% of spell damage), `haste` (`spellCd()` cuts cooldowns 30%), `manaregen` (+8 MP/s), `thorns` (reflect 40% of melee damage). `gearStats` appends the power text. Looting one triggers `celebrateArtifact()` — the crimson variant of the celebration (`celebrateDrop(g,'art')`, `ART_COLS`, `sfxArtifact()`). Artifacts can't be forged further (`canUpg` caps at rar≥4) and persist as normal gear objects in saves.
- **NPCs**: Elder Mira, Guard Tomlin, Ranger Sylva, Sage Oriax, Scholar Aldric, Seer Vesper (quest givers — each may hold several quests across the story; `npcQuest()` resolves a giver's current quest by matching `quest.giver` to the NPC name, preferring active > newly available > still-locked > last completed, so the `q` field on NPC data is only a marker, not a single fixed quest); Forgemaster Bren (gear upgrades: gold + monster materials per `UPG` tier table, `upgradeGear()` rescales stats by rarity multiplier); Bounty Board (repeatable hunts: `genBounty()` scales target/reward to player level — `n = (8–12) × 5` kills, XP = the base formula × 2, progress tracked on `G.bounty`, pays gold + XP only (no gear cache), re-offers immediately); Storage Chest (a treasure-chest sprite NPC in the hub: deposit/withdraw items between bag and `G.storage`, base 10 slots, expandable in 10-slot blocks via `expandStorage()` at a doubling cost — `storageCost()` = 2000g × 2^expansions; when the 16-slot bag is full, `addItem` auto-routes the new item into storage via `bagAdd`, and only loses it if storage is full too)
- **Quests**: 23 story quests forming one continuous sequential story chain (plus 5 guild-introduction side quests — see the end of this bullet) — 15 in Act 1 (the Hollow Rift arc), 7 in **Act 2: The Emberfall Saga**, and the q23 raid finale (see The Riftheart raid below) (q16–q22, gated on q15; Malachar the Ash Sage gathers the fallen rift's embers to forge a Second Shattering). Act 2 keeps the per-zone pattern (story → rare-hunt → boss for zones 7 and 8), adds hub giver **Envoy Sable** alongside Seer Vesper and Sage Oriax, hands out fixed gear (`emberweave_robe`, `phoenix_staff`, `glacier_mantle`), and ends with q22 (`tp:9`) teleporting into the Ashen Sanctum to fight `ash_sage`, who (like `hollow_oracle`) drops a guaranteed Artifact. Each `prev` field gates on the prior quest. The chain is ordered **zone-by-zone** (all of Zone 1, then Zone 2, …, then the finale); within each zone the order is story quest → rift-relic hunt → boss kill, so low-level/low-zone quests always come before higher-zone ones. The `QUESTS` array order matches the chain order, but the `prev` links — not array position — define the gating (ids stay stable, e.g. `q7`/`q8` are Zone 1 even though numbered after the `q3`–`q6` story quests). Story beats (the Veyra reveal, the Shattering, sealing the door) are woven into the per-zone quests rather than front-loaded. For **each combat zone** there is a rare-hunt quest (collect that zone's 1% relic) and a boss-kill quest (`type:'kill'` against the zone's boss `t`, e.g. `slime_sov` — boss kills are recorded in `G.kills` by `killM` just like normal monsters). The regular-monster kill quests pay **2× XP**; their kill counts were trimmed to ~half (slime 8, goblin 10, bat 13, golem 8, skeleton 13, wraith 10, magmite/frostmaw 13) to cut grind (C5). q15 ("Into the Hollow Rift", Seer Vesper, `rlvl:18`) is the finale: accepting it (`tp:5`) teleports the player into the Hollow Rift to fight `hollow_oracle`, an enlarged/recolored reuse of the Fallen Oracle (`scale` field → `m.bscale`, used by the boss draw + spawn). The finale is a *soft* gate — `rlvl:18` plus brutal tuning (q13/q14 gate at 17/18 so the chain reaches it); q14 hands out a guaranteed Legendary (`oracle_staff`) so the player realistically has the Legendary the lore demands. Each quest object carries narrative fields: `txt` (offer), `done` (turn-in reveal), `after` (post-completion), `lock` (shown while the previous quest is unfinished **or** while the level requirement is unmet); `{name}` in any of them substitutes the player name via `qtxt()`. Tasks are `{type:'kill',tgt,n}`, `{type:'col',item,n}`, or `{type:'talk',tgt:npcName,n}` (credited by `openDlg` via `questCredit('talk',npc.name)` before it routes to any special shop/forge/rift/city/codex handler; progress shares the per-quest `kills` map keyed by NPC name). Beyond the story chain there are **five guild-introduction side quests** (`side:true`, ids `n1`–`n5`, appended after the story quests so `npcQuest` offers story first): level-gated "go meet the service NPC" mini-quests that introduce Forgemaster Bren (Elder Mira, lv3), Chronicler Ily (Scholar Aldric, lv5), Master Builder Sora (Guard Tomlin, lv8), and — gated on q15 — Riftwarden Kael (Seer Vesper) and Astralwright Nyx (Sage Oriax). They sit outside the `prev`-chain (`prev:null` or `'q15'`), and an NPC who is the target of an active, uncredited talk task gets the gold `!` marker in the draw loop. Progress is tracked **per quest** in `G.questProg[id] = {kills,items}`, which `acceptQ` resets to zero on acceptance — so kill/loot counters start fresh and don't inherit lifetime `G.kills` or current inventory. `killM`/`addItem` call `questCredit('kill'|'col', key)` to advance every active quest that wants that target; `qCount(id,task)` reads the per-quest count, and both `isQDone` and `qProg` go through it. (Pre-`questProg` saves are migrated in `applySave` by seeding each active quest's progress from the legacy counts, capped at the requirement, so in-flight quests aren't wiped.) `qProg`/`monName` render kill targets by display name, and `col` progress lines append the dropping monster via `itemSource()` (e.g. "Pulsing Rift Seed (drops from Slime): 0/1") so the quest tab tells you where to hunt. The quest tab itself (`renderQP`) is a **hierarchy**: the active story quest is pinned on top with live progress (`.qtrack`), any other active threads (side quests / bounty) list below, all available-but-unaccepted quests collapse into one "N new quests in Aethon City" line (`.qavail`) so the town's `!` markers never pile up in the panel, and completed quests collapse to a single count. Shop NPCs carry a `lore` line shown atop their shop dialog.

## Development Conventions

- All additions go directly into `index.html` — do not split into separate files.
- Follow the existing section structure; new systems belong in the section that owns their domain (e.g., new audio in the Audio Engine section).
- New game content (monsters, items, spells, quests) is defined as data objects/arrays near their existing counterparts, not scattered inline.
- Canvas draw calls use `ctx.save()` / `ctx.restore()` around any state changes (transforms, compositing).
- All new properties added to `G` should have an initial value set where `G` is first defined, not lazily.
